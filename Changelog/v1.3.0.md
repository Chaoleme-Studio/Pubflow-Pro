# PubFlow v1.3.0 发布说明

**发布日期：** 2026-07-19
**版本号：** 1.3.0
**标签：** `v1.3.0`

## [1.3.0] - 2026-07-19

## 主要更新

### 项目复刻

- “我的视频”操作列增加“复刻”，仅复用源项目的标题、描述、话题、活动、正文和平台设置。
- 复刻不带入视频、封面、音乐或图片，也不向新项目复制源项目文件；素材需重新选择。
- 复刻项目拥有独立 `projectId`，源项目及其发布记录保持不变。
- 未开始分发前连续复刻其他项目时，复用并覆盖同一个复刻草稿项目，避免产生多条无效副本。
- 复刻项目重新选择源项目原来使用的平台，但所有平台状态从 `pending/skipped` 重新开始；发布时间重置为立即发布。

### 话题填写与平台交互

- 话题按 `#话题 → 等待 800ms → Enter → 等待 800ms → 空格` 的顺序逐个输入，间隔可在设置中调整。
- 抖音和知乎改用浏览器级可信点击与输入，解决抖音只识别第一个标签、后续产生换行的问题。
- 知乎会点击并激活 `.EditorArea` 内部真正的 Draft.js `contenteditable`，再填入描述和话题。
- B站所有非原生点击入口统一走安全点击封装，修复 `e.click is not a function`。

### 工作区与历史项目

- 标准 v2 项目以 `projectId` 作为唯一身份，不再依赖目录名猜测或版本兼容分支。
- 工作区选择前严格校验 `pubflow-data.json`、`projects/` 和每个 `project.json`；`dist`、`.output` 等构建目录不会再被初始化成工作区。
- `dist` 与 `.output` 使用固定扩展 ID，避免不同加载路径形成两套浏览器缓存和目录句柄。
- 已确认测试工作区包含 65 个快照、41 个逻辑项目和 0 个无效目录。

### 状态与发布稳定性

- 编辑和复刻会将嵌套的 Vue Proxy 平台设置深度转为普通 JSON 数据，避免 `structuredClone` 中断原项目的视频和封面恢复。
- “我的视频”中 `filled` 和 `published` 状态统一显示为绿色完成状态。
- 只有未来的有效时间才会恢复为定时发布，过期或未勾选的时间按立即发布处理。
- 描述末尾已有的 `#话题` 会与独立话题字段合并去重，避免多平台重复填写。
- 正式构建脚本兼容 macOS Bash 3.2，可完整加载带引号的 ENV 配置。

## 发布方式

- GitHub Release 正文继续固定读取根目录 `CHANGELOG.md`。
- 历史说明保存在 `Changelog/v1.3.0.md`；后续发布不需要修改 `.github/workflows/release.yml`。
- 发布附件：`pubflow-extension.zip`。
